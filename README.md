# Bitunix Demo Auto-Trader (ربات اندروید)

اپی که سیگنال‌های اسپاتِ ربات پایتونیِ LBank را از کانال تلگرام می‌خواند و
**در نسخه‌ی دموی اپ بیت‌یونیکس روی موبایل** به‌صورت خودکار سفارش می‌گذارد:

* نوع سفارش: **LIMIT** (مقدار لیمیت = قیمت ورودِ سیگنال)
* مارجین: **۱۰ دلار**
* اهرم: **۱۰x – حالت Isolated**
* حجم (Qty) = ۱۰۰ ÷ قیمت لیمیت (یعنی ۱۰۰ دلار پوزیشن)
* **TP و SL** هم به‌صورت قیمت‌های مطلق از خود سیگنال ست می‌شوند
* فقط سیگنال‌هایی که نمره‌شان **۹/۱۰ یا ۱۰/۱۰** است (قابل تغییر)
* فقط **LONG** (پیام «ناامن» هیچ‌وقت سفارش نمی‌سازد)

این پروژه همین حالا داخل همین پوشه **بیلد شده** و APK آماده این است:

```
app/build/outputs/apk/debug/app-debug.apk
```

یعنی اگر فقط می‌خواهی روی گوشی نصبش کنی، همان فایل بالا را بردار و برو به بخش
«۴) نصب روی گوشی». بخش‌های ۱ تا ۳ برای وقتی است که خودت بخواهی از صفر بیلد کنی.

## ۰) اپ از چه چیزی تشکیل شده

| فایل | کار |
|---|---|
| `SignalParser.kt` | خواندن پیام کانال؛ هم خط ماشین‌خوان `#SIG {...}` و هم متن فارسی |
| `TelegramSource.kt` | شنود مستقیم کانال تلگرام (بدون کامپیوتر) |
| `SignalClient.kt` | پل اختیاری WebSocket از کامپیوتر |
| `SignalFormat.kt` | ساخت اعداد نهایی (`QTY`, `ENTRY_PRICE`, `TP_PRICE`, `SL_PRICE`, …) |
| `ActionPlan.kt` + `Plans.kt` | «دستور معاملات»: لیست گام‌های لمس/تایپ روی اپ بیت‌یونیکس |
| `BitunixAccessibilityService.kt` | موتور اجرا با Accessibility (لمس و تایپ خودکار) |
| `SignalService.kt` | سرویس پس‌زمینه که همیشه بیدار است |
| `MainActivity.kt` + `activity_main.xml` | صفحه‌ی تنظیمات و لاگ |
| `app/src/test/.../SignalParserTest.kt` | ۱۱ تست خودکار روی پیام واقعی |

پلن پیش‌فرض داخل `Plans.kt` است و با دکمه‌ی «دستور معاملات» در خود اپ قابل ویرایش است
(نیازی به بیلد مجدد برای تغییر متن دکمه‌ها نداری).

## ۱) روش اول (پیشنهادی): بیلد ابری با GitHub Actions — بدون نصب هیچ چیز

روی سیستم خودت **نه اندروید استودیو، نه JDK، نه SDK** لازم نیست. GitHub با
سرور خودش APK را می‌سازد و تو فقط دانلودش می‌کنی.

1. یک اکانت GitHub بساز (اگر نداری).
2. یک ریپازیتوری **Private** جدید بساز، مثلاً `bitunix-demo-bot`
   (گزینه‌ی «Add a README» را نزن).
3. فایل zip پروژه را (همین پوشه، بدون پوشه‌ی `app/build`) از حالت zip در بیار.
4. در صفحه‌ی ریپازیتوری: **Add file → Upload files** و **همه‌ی محتوای پوشه‌ی
   `BitunixDemoBot`** را آپلود کن (شامل پوشه‌های `app`, `gradle`,
   `build.gradle.kts`, `settings.gradle.kts`, `gradlew`, `gradlew.bat` و پوشه‌ی
   مخفی `.github`). سپس **Commit changes**.
   * نکته: پوشه‌ی مخفی `.github` را حتماً آپلود کن، وگرنه بیلد ابری اجرا نمی‌شود.
     (اگر با گوشی آپلود می‌کنی، از اپ GitHub Desktop یا از کامپیوتر استفاده کن.)
5. برو به تب **Actions**. ورک‌فلوی `Build Android APK` خودش شروع می‌شود؛ اگر نشد:
   از سمت چپ همان ورک‌فلو را انتخاب کن و **Run workflow** بزن.
6. منتظر بمان (حدود ۲ تا ۵ دقیقه).
7. وقتی تیک سبز شد، روی همان اجرا کلیک کن و در پایین صفحه بخش **Artifacts**:
   * `BitunixDemoBot-debug-apk` → دانلودش کن و از حالت zip خارج کن (داخلش `app-debug.apk` است).
   * `unit-test-report` → گزارش ۱۱ تست (اختیاری).
8. حالا برو به بخش «۴) نصب روی گوشی».

> هر بار که فایلی را در گیت‌هاب تغییر بدهی، GitHub خودش دوباره APK می‌سازد.

## ۲) روش دوم: بیلد روی کامپیوتر خودت (بدون اندروید استودیو)

فقط سه چیز لازم است: **JDK 17**، **Gradle wrapper (داخل پروژه هست)** و
**Android SDK command-line tools**. اندروید استودیو لازم نیست.

### ویندوز

1. **JDK 17** را نصب کن: از Adoptium → `OpenJDK 17 (x64) MSI` → موقع نصب گزینه‌ی
   *Set JAVA_HOME* را روشن بگذار.
   `java -version` باید `17` را نشان بدهد.
2. **Android command-line tools** را دانلود کن:
   <https://developer.android.com/studio#command-tools> →
   `commandlinetools-win-*_latest.zip`
3. آن را در مسیر `C:\Android\cmdline-tools\latest` باز کن (طوری که
   `C:\Android\cmdline-tools\latest\bin\sdkmanager.bat` وجود داشته باشد).
4. در PowerShell:
   ```powershell
   $env:ANDROID_HOME="C:\Android"
   cd C:\Android\cmdline-tools\latest\bin
   .\sdkmanager.bat --sdk_root=C:\Android "platform-tools" "platforms;android-34" "build-tools;34.0.0"
   .\sdkmanager.bat --sdk_root=C:\Android --licenses   # همه را y بزن
   ```
5. برو داخل پوشه‌ی پروژه (`BitunixDemoBot`) و در همان مسیر یک فایل
   `local.properties` بساز با این خط:
   ```
   sdk.dir=C\:\\Android
   ```
6. بیلد:
   ```powershell
   .\gradlew.bat testDebugUnitTest assembleDebug
   ```
   خروجی: `app\build\outputs\apk\debug\app-debug.apk`

### لینوکس / مک

```bash
# ۱) JDK 17
sudo apt install -y openjdk-17-jdk        # مک: brew install openjdk@17
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64

# ۲) اندروید command-line tools
mkdir -p ~/android/cmdline-tools && cd ~/android/cmdline-tools
# فایل commandlinetools-linux-*_latest.zip را از همان لینک بالا دانلود و باز کن
mv cmdline-tools latest
export ANDROID_HOME=~/android

# ۳) نصب پلتفرم ۳۴
~/android/cmdline-tools/latest/bin/sdkmanager --sdk_root=$ANDROID_HOME \
  "platform-tools" "platforms;android-34" "build-tools;34.0.0"
yes | ~/android/cmdline-tools/latest/bin/sdkmanager --sdk_root=$ANDROID_HOME --licenses

# ۴) بیلد
cd /path/to/BitunixDemoBot
echo "sdk.dir=$ANDROID_HOME" > local.properties
chmod +x gradlew
./gradlew testDebugUnitTest assembleDebug
```

نتیجه‌ی موفق:
```
BUILD SUCCESSFUL
app/build/outputs/apk/debug/app-debug.apk
```

> اگر `Could not find tools.jar` یا خطای مشابه دیدی، یعنی JDK اشتباه است؛
> باید دقیقاً **JDK 17** باشد و `JAVA_HOME` به آن اشاره کند.
> اگر ROOT پروژه را عوض کردی، فایل `local.properties` را خودت بساز
> (این فایل مخصوص هر کامپیوتر است و نباید در گیت باشد).

## ۳) اجرای تست‌ها (اختیاری ولی توصیه‌شده)

```bash
./gradlew testDebugUnitTest
# گزارش: app/build/reports/tests/testDebugUnitTest/index.html
```

۱۱ تست که روی **پیام واقعیِ ربات پایتونی** (`app/src/test/resources/sample_signal_msg.txt`)
اجرا می‌شوند و این‌ها را تضمین می‌کنند:

* خواندن خط `#SIG {"s":"SAMPLE_USDT","e":12.0574242964,"tp":...,"sl":...}`
* خواندن همان پیام در حالتی که خط `#SIG` نباشد (روش پشتیبان)
* پیام «ناامن» هرگز به سفارش تبدیل نشود
* عدد Qty: `۱۰۰ ÷ 12.0574242964 = 8.293645`
* قیمت‌ها بدون نماد علمی و با رقم‌های درست (`12.0574243`, `12.23828566`, `10.98514832`)
* همه‌ی جای‌گذارها در پلن معاملات معنی داشته باشند و گام‌های حیاتی اختیاری نباشند

## ۴) نصب روی گوشی

1. فایل `app-debug.apk` را به گوشی منتقل کن (کابل، بلوتوث، تلگرام Saved Messages…).
2. در گوشی اجازه‌ی نصب از منبع ناشناس را بده:
   * اندروید ۸+: Settings → Apps → Special access → **Install unknown apps** →
     همان اپی که APK را باز می‌کند (Files/Chrome/Telegram) → Allow.
3. روی APK بزن → **Install**. اگر Play Protect هشدار داد: **Install anyway**
   (این اپ دیباگ و بدون امضای فروشگاهی است).
4. اپ با نام **Bitunix Demo Bot** نصب می‌شود.

| اهرم | `10` | |

## ۶) روشن کردن سرویس دسترسی‌پذیری (اجباری)

بدون این مرحله، اپ فقط سیگنال می‌گیرد و هیچ سفارشی نمی‌گذارد.

1. دکمه‌ی **«باز کردن تنظیمات دسترسی‌پذیری»** را در اپ بزن.
2. در لیست دنبال **Bitunix Demo Bot** بگرد.
3. روشن کن → پیام هشدار اندروید را **Allow** کن.
4. برگرد به اپ؛ چراغ «سرویس دسترسی‌پذیری: روشن» سبز می‌شود.
5. در اندروید بهینه‌سازی باتری را برای این اپ خاموش کن (اپ خودش درخواست می‌دهد)
   تا سرویس در پس‌زمینه کشته نشود.
6. در بیت‌یونیکس هم از قبل **لاگین** باش و اپ را در حالت **دمو** بگذار.

## ۷) تست بی‌خطر (خیلی مهم — قبل از معامله‌ی واقعی)

**تست الف) تحلیل پیام بدون لمس چیزی:** در اپ دکمه‌ی
**«اجرای آزمایشی روی یک پیام کانال»** را بزن و متن کامل یک پیام کانال (یا محتوای
فایل `tools/sample_signal_msg.txt`) را داخلش بچسبان و «تحلیل و اجرا» را بزن.
در لاگ باید ببینی:

```
تحلیل پیام: SAMPLE_USDT → SAMPLEUSDT entry=12.0574243 tp=12.23828566 sl=10.98514832 score=10
مقدار محاسبه‌شده: qty=8.293645 (10$ × 10x)
```

این یعنی کل زنجیره (پارس → محاسبه) درست است.

**تست ب) اجرای واقعی روی اپ با حالت خشک:** «حالت خشک» را روشن و
**«فعال باشد»** را هم روشن کن، «شروع شنود» را بزن. حالا در بیت‌یونیکس (دمو)
هر سیگنالی که برسد، در لاگ می‌بینی کدام گام کجا کلیک می‌کرد و هیچ لمس واقعی
صورت نمی‌گیرد.

**تست ج) کالیبره کردن پلن — این مرحله را جدی بگیر:**
متن دکمه‌های اپ بیت‌یونیکس ممکن است با پلن پیش‌فرض فرق داشته باشد. برای همین:

1. در بیت‌یونیکس برو به صفحه‌ای که می‌خواهی سفارش در آن ثبت شود (صفحه‌ی فیوچرز
   یک ارز، فرم سفارش).
2. در اپ دکمه‌ی **«ذخیره‌ی ساختار صفحه»** را بزن.
3. فایل ذخیره‌شده در این مسیر است:
   `Android/data/com.lbank.btdemobot/files/ui_dump_<عدد>.txt`
4. کپی‌اش کن روی کامپیوتر، بازش کن و دنبال `text=` و `desc=` دکمه‌ها بگرد
   (مثلاً دنبال `Limit`, `Price`, `Amount`, `Buy`, `Confirm`, `TP/SL`).
5. در اپ دکمه‌ی **«دستور معاملات»** را بزن و متن JSON پلن را با متن‌های واقعی
   اپت هماهنگ کن. نمونه:

```json
{"action":"click","by":"text","value":"Limit","delay":900}
{"action":"setText","by":"text_contains","value":"Amount","text":"{QTY}"}
```
   «Save» بزن. (دکمه‌ی «بازگردانی پیش‌فرض» همیشه پلن اولیه را برمی‌گرداند.)

**تست د) اجرای واقعی با ۱۰ دلار:** «حالت خشک» را خاموش کن، «فعال باشد» روشن
بماند و با فیلتر «حداقل نمره = ۹» بگذار یک سیگنال واقعی بیاید. اولین معامله را
خودت در بیت‌یونیکس چک کن.

## ۹) ارتباط با ربات پایتونی LBank

* لازم نیست کار خاصی بکنی: اپ همان پیام‌های کانال را می‌خواند.
* ربات پایتونی (`lbank_spot_signals.py`) الان در انتهای هر پیام یک خط اضافه می‌کند:
  `<code>#SIG {"t":"SIG","s":"SOL_USDT","d":"LONG","e":12.05,"tp":12.23,"sl":10.98,"q":10}</code>`
  این خط، «قرارداد» بین ربات و اپ است: سریع، بدون ابهام و مقاوم در برابر تغییر متن فارسی.
* اگر اپ یک پیام را نشناخت، پیام مشکلی ندارد؛ روش پشتیبان متن فارسی را می‌خواند.

## ۱۱) نکات مهم و محدودیت‌ها

* همه‌چیز روی حساب **دمو**ی بیت‌یونیکس هدف‌گذاری شده؛ مسیرهای لمس همان اپ دموست.
* امکان خطای اجرای خودکار روی موبایل وجود دارد (تغییر UI، کندی گوشی، تغییر
  نسخه‌ی اپ). برای همین «حالت خشک» و «کالیبراسیون با ui-dump» گذاشته شده است.
* اپ هیچ کلید API بیت‌یونیکس نمی‌خواهد و نمی‌گیرد؛ فقط با UI کار می‌کند، پس اگر
  اپ بیت‌یونیکس بسته/لاگ‌اوت باشد، سفارش ثبت نمی‌شود.
* این ابزار توصیه‌ی سرمایه‌گذاری نیست؛ مسئولیت هر معامله با خودت است. حتماً
  اول با دمو و مبلغ کم تست کن.
